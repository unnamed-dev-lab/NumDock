# 国际化维护

NumDock 使用 i18next 26、react-i18next 17，支持英文 `en` 与简体中文 `zh-CN`。语言按钮位于登录／注册页、工作区和错误页右上角，使用已有的 Base UI DropdownMenu 与 beUI Button 组合。

## 请求与切换

根 loader 按有效 `numdock.locale` Cookie → `Accept-Language` → 英文解析语言。支持按 q 权重选择，忽略 q=0 的语言；不支持或损坏的偏好回退到下一来源。SSR 为每次渲染创建独立 i18next 实例，资源同步初始化，服务器与浏览器使用相同的 loader 数据。响应标记 `Content-Language`、`Vary: Cookie, Accept-Language` 和 `Cache-Control: private, no-store`。

选择语言后，将偏好保存为一年有效、Path=/、SameSite=Lax 的 Cookie；HTTPS 下附加 Secure。Cookie 仅包含语言，不包含身份凭据。根 loader 重新验证后同步更新文案、HTML lang 和路由元信息，保留表单及 QueryClient。当前工作台路由没有语言前缀。

## 添加文案

在 `app/lib/i18n/locales/en.json` 和 `zh-CN.json` 中添加相同语义键，例如 `workspace.noNumbersYet`；组件使用 `useTranslation()` 的 `t()` 获取。当前采用扁平资源，前缀用于业务分组，资源规模较小时同步加载两种语言，避免额外请求或切换闪动。

变量通过 `t(key, { name })` 插值。数量参考 `common.workspaceCount_one` 与 `_other`，使用 `t("common.workspaceCount", { count })`。表单错误保存资源键，在渲染时翻译；API 错误保留原始对象，由 `errorMessage(error, t)` 按错误码转换，所以已有错误也能随语言更新。

不翻译组织／用户名称、短信正文、供应商数据、技术协议名、路径或权限范围标识。角色显示名称使用 `roleLabel`；日期使用 `formatDate(timestamp, i18n.language)`，时区保持 UTC。现有页面没有可用的余额或价格，不引入虚构金额展示。

## 验证

- `pnpm typecheck`：路由和翻译键类型检查。
- `pnpm lint`：含中英文资源键、非空值与插值参数检查。
- `pnpm exec playwright test tests/i18n.spec.ts`：SSR 请求隔离、无 JavaScript 首屏、语言持久化、保留输入与校验、错误码映射、工作区页面和窄屏深色交互。此文件使用明确的测试拦截响应，不依赖真实 API。
- `pnpm test:e2e`：包含依赖开发 Go API／PostgreSQL 的身份完整流程。

实现依据：[react-i18next SSR](https://react.i18next.com/latest/ssr)、[i18next TypeScript](https://www.i18next.com/overview/typescript)。
