# API error reference

All API failures use one JSON envelope. HTTP status code, stable `code`, and
`request_id` are the contract. `message` is user-facing copy and may change or
be translated by the frontend.

```json
{
  "code": "validation_failed",
  "message": "Enter a valid email address.",
  "request_id": "3d4f6a9b2c1e4f67890a1b"
}
```

The response also includes `X-Request-ID` with the same value as `request_id`.
The ID is generated by the server; client-supplied values are ignored.

## Status and code mapping

| HTTP | Code | When it occurs |
| --- | --- | --- |
| `400` | `invalid_request` | Malformed JSON, unknown field, extra JSON value |
| `400` | `validation_failed` | Invalid email, password, name, organization name, limit, or offset |
| 400 | terms_required | Number purchase submitted without affirmative authorized-use confirmation |
| 400 | invalid_rental_period | Missing or unsupported purchase term; choose 3, 7 or 30 days |
| `401` | `invalid_credentials` | Login email/password is incorrect |
| `401` | `unauthenticated` | Session cookie missing, expired, or revoked |
| `403` | `csrf_failed` | Origin mismatch or CSRF token missing/invalid |
| `404` | `not_found` | Unknown route |
| `405` | `method_not_allowed` | Route exists but not for this HTTP method |
| `409` | `account_unavailable` | Registration email cannot be used; intentionally generic |
| `413` | `payload_too_large` | Auth request body exceeds 8192 bytes |
| `415` | `unsupported_media_type` | Request body is not `application/json` |
| `429` | `rate_limited` | IP or email authentication limit exceeded |
| `500` | `internal_error` | Unexpected server or database failure |
| `503` | `not_ready` | `/readyz` cannot reach PostgreSQL |
| `504` | `request_timeout` | Request exceeded the 15-second server timeout |

## Rate limiting

Register and login use persistent fixed-window counters:

- 20 attempts per client IP per minute.
- 10 attempts per normalized email per minute.

The response is `429 rate_limited` with `Retry-After: 60`. IP resolution uses
the direct connection peer unless the peer is listed in `TRUSTED_PROXIES`;
`X-Forwarded-For` is parsed from right to left across trusted proxies.

## Timeout behavior

The server cancels request contexts after 15 seconds. If a handler observes the
deadline, it returns `504 request_timeout`. The timeout middleware only writes a
504 when no response has started, so it never overwrites a handler response.

## Security and privacy

- 500 responses never include database error text, SQL, password hashes, or
  submitted message content.
- Server logs record an error type and request ID, not raw database errors.
- Do not include passwords, session tokens, CSRF tokens, or message content in
  support requests; include the request ID instead.
- The frontend maps stable `code` values to localized messages and does not
  display arbitrary server diagnostics.
